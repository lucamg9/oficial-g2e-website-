# G2E Website — Claude Code Operating Guide

## 1. Role

You are the lead product strategist, UX architect, creative director, frontend engineer, motion designer, SEO strategist, and performance optimizer for **G2E — Green to Energy**.

Your job is to rebuild and upgrade the G2E website into a premium, highly credible, visually impressive, and strategically structured corporate website.

This is not a small redesign.
This is a serious client-facing website for a clean-tech company with high expectations.

The website must feel:

- professional
- scientific
- innovative
- environmentally focused
- premium
- bright
- transparent
- trustworthy
- fast
- polished
- investor-ready
- stakeholder-ready

Do not make it look like a generic startup template.
Do not make it look like a fake futuristic demo.
Do not overdesign.
Do not sacrifice performance.

The final result should feel like:
**“Wow, this company is serious, advanced, and worth paying attention to.”**

## 2. Project Summary

**G2E — Green to Energy** is a Mexican clean-tech company that transforms waste into value.

### Core company facts
Use the following as the source of truth:

- G2E turns organic waste into **hydrochar**
- Hydrochar can replace **mineral coal**
- It can also regenerate farmland soil
- It helps decarbonize the steel industry
- The company works with **UNAM**, the **Mexican Government**, and international partners
- G2E operates the **world’s largest hydrothermal carbonization plant** processing municipal organic waste
- G2E’s story includes:
  - rural development roots
  - biomass / gasification / biochar experience
  - partnership with UNAM
  - demonstration center
  - Mexico City plant
  - Phase II expansion
  - large-scale replication strategy
- The company’s future includes major scale-up through modular replication

### Key products / outcomes
G2E should be positioned around three main value pillars:

1. **Biological fertilizer**
2. **Mineral coal replacement**
3. **Premium carbon credits**

### Main business direction
The website is a presentation and business development tool.
Its main objective is to:
- attract attention
- build trust
- explain the company clearly
- drive contact
- support stakeholder and investor interest

## 6. Motion / 3D Direction

Use motion and 3D as a storytelling tool, not as decoration.

### Motion should be:
- subtle
- cinematic
- smooth
- elegant
- purposeful
- performance-conscious

### Use 3D or motion for:
- hero storytelling
- technology explanation
- process visualization
- impact visualization
- key transitions between sections

### Avoid:
- long heavy loops
- excessive animation everywhere
- decorative effects with no narrative value
- anything that reduces trust or speed

The goal is a hybrid of:
- visual wow
- clarity
- speed
- professionalism

Prefer:
- a few highly polished scenes
over

The website should be structured around the company story and the stakeholder journey.

2. **Technology**
3. **Solutions**
4. **Impact**
5. **Projects**
6. **Demonstration Center**
7. **Hydrocarbon / Carbon Credits**

### What each page should do

- Introduce G2E quickly
- Explain the core value proposition
- Present the main CTA
- Lead to the most important sections
- Create a strong first impression

#### 2. Technology
- Explain what G2E uses
- Explain how the technology works
- Show tools, processes, and scientific credibility

- Consider a form to request more information

#### 3. Solutions
- Explain what G2E solves
- Show the biggest solution clearly
- Make the value proposition easy to understand
- Highlight the impact for industry and cities

#### 4. Impact
- Show what problem G2E solves
- Explain why G2E matters
- Use numbers, facts, and visual storytelling
- Show the difference between “with G2E” and “without G2E”

#### 5. Projects
- Show current projects
- Explain what G2E is building
- Make the project vision clear
- Include educational / request-more-info CTAs

#### 6. Demonstration Center
- Present the station / offices / demo location
- Explain what it is
- Make it feel real and tangible
- Add a visit CTA

#### 7. Hydrocarbon / Carbon Credits
- Explain the process clearly
- Show how carbon credits are generated
- Show why they are high-quality / premium
- Add proof, data, and educational diagrams

#### 8. Contact
- Clean contact flow
- Name
- Email
- Phone
- Location
- Call to action
- Make it simple and direct

#### 9. Online Presence
- Show articles, PDFs, mentions, social presence, and proof of public activity
- Reinforce credibility
- Show where G2E is visible online

#### 10. About Us
- Team
- values
- working style
- transparency
- company culture
- human credibility

## 12. Development Rules

### Rule 1: Always read first
Before taking any action, always read:
- `CLAUDE.md`
- `project_specs.md`

If either file does not exist, create it before doing anything else.

### Rule 2: Define before you build
Before writing any code:
1. Create or update `project_specs.md`
2. Define:
   - what the website does
   - who it is for
   - tech stack
   - pages and user flows
   - data models if relevant
   - third-party services if relevant
   - what “done” looks like
3. Show the file
4. Wait for approval

No code should be written before this file is approved.

### Rule 3: Look before you create
Always inspect existing files before creating new ones.
Do not build until you understand the current structure.

### Rule 4: Test before you respond
After code changes:
- run the relevant tests
- run the build
- check for runtime errors
- verify in the browser if possible

Never say “done” if the code is untested.

### Core rule
Do exactly what is asked.
Nothing more.
Nothing less.
If something is unclear, ask before starting.

## 13. File Structure Guidance

Keep the structure clean and simple.

Recommended folders:
- `/app` → pages and routes
- `/components` → reusable UI blocks
- `/components/sections` → page sections
- `/components/ui` → shared UI primitives
- `/lib` → helper functions
- `/content` → text/content sources if needed
- `/public` → images, media, static files
- `project_specs.md` → project blueprint
- `CLAUDE.md` → operating instructions

Do not create new top-level folders without asking first.
